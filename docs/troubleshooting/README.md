# 开发问题与经验记录

仅记录可复现、影响较大或有长期参考价值的故障、根因、修复与规避措施。未确认的根因必须标记为假设；不记录所有临时错误、重复日志或日常工作流水。遵循 [开发工作守则](../development/coding_guidelines.md)。

## 当前记录

当前尚无生产应用故障记录；Rig PoC 的 CI 依赖弃用警告见 [验证报告](../testing/rig_sdk_validation.md)。按实际问题逐步增加主题文档，不预先建立空分类文件。

## 记录模板

在对应主题 Markdown 中新增独立条目，采用稳定问题编号（如 DD-ISSUE-0001）。关联 Git commit、测试或 ADR（如有）。

| 字段 | 填写内容 |
|---|---|
| ID / 标题 | 唯一编号与问题摘要 |
| 环境 | OS、依赖版本、分支/提交、必要配置（脱敏） |
| 现象与影响 | 实际错误、影响范围及严重程度 |
| 复现条件与步骤 | 前置条件、输入、操作和观察结果 |
| 根本原因 | 确认的根因及证据；未确认则写待验证假设 |
| 解决方案 | 实际修改、适用边界和关联提交 |
| 临时规避 | 适用条件、副作用及何时撤销；没有则不适用 |
| 预防措施 | 相关设计约束、诊断脚本或回归用例 |
| 验证 | 命令、环境、预期与实际结果、测试/报告链接 |
| 状态 | Open / Mitigated / Resolved；更新日期、遗留风险 |

## 经验复用

解决问题后先判断是否值得长期维护。通用规则更新相应专题文档或开发守则，重要技术决策记录 ADR，可自动验证的行为补充 tests，可执行诊断归 scripts。只有稳定、重复且通用工具无法覆盖的复杂流程才评估封装 Skill；不另建与本目录重复的知识库。禁止将真实密钥、敏感媒体或未脱敏生产日志提交到公开仓库。
